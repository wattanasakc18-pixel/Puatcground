# Puatc Ground

เว็บแอปสำหรับวิทยาลัย: ระบบลงชื่อตัวแทนทำกิจกรรมล่วงหน้า + ปฏิทินกิจกรรม
สร้างด้วย React + Vite + Tailwind CSS v4 + Supabase (PostgreSQL, Auth, Storage, RLS)
ภาษาในหน้าเว็บเป็นภาษาไทยทั้งหมด แสดงวันที่เป็น พ.ศ. เขตเวลา Asia/Bangkok

## ความต้องการของระบบ

- Node.js 24 ขึ้นไป (พัฒนาบน Windows)
- บัญชี Supabase (ฟรีก็ใช้ได้)

## 1) ตั้งค่า Supabase

1. สร้างโปรเจกต์ใหม่ที่ https://supabase.com/dashboard (จด Project URL และ publishable key ไว้)
2. **ปิด Confirm email**: ไปที่ Authentication → Sign In / Providers → Email แล้วปิด "Confirm email"
   (ระบบใช้รหัสผ่านกับอีเมลสังเคราะห์ `<รหัสนักศึกษา>@puatc.local` จึงไม่มีการยืนยันอีเมลจริง)
3. เปิด SQL Editor แล้ววางเนื้อหาไฟล์ [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์ รันครั้งเดียว
   - จะได้ตารางทั้งหมด, RLS, trigger, RPC, view, bucket `avatars`/`form-uploads` และรายชื่อแผนกวิชาจริง 10 แผนก
   - ไม่มีข้อมูลตัวอย่างอื่นใด กิจกรรม/หมวดกิจกรรม/ผู้ใช้ คุณสร้างเองผ่านหน้าเว็บ
4. ถ้าต้องการล้างแล้วเริ่มใหม่: รัน [`supabase/reset.sql`](supabase/reset.sql) ก่อน แล้วรัน `schema.sql` ใหม่
   (reset ไม่ลบผู้ใช้ใน Authentication — ลบผู้ใช้เองได้ใน Dashboard → Authentication → Users ถ้าต้องการ)

> **อัปเดตระบบอนุมัติกิจกรรม:** ถ้าเคยรัน `schema.sql` เวอร์ชันแรกไปแล้ว (ก่อนมีบทบาทผู้จัดกิจกรรม/ระบบอนุมัติ)
> ให้รัน [`supabase/migration-organizer-approval.sql`](supabase/migration-organizer-approval.sql) ใน SQL Editor อีกครั้งเดียว
> เพื่อเพิ่มคอลัมน์ `created_by`/`approval_status`, RLS และ trigger ใหม่ โดยกิจกรรมเดิมจะถูกตั้งเป็นอนุมัติแล้วทั้งหมด
> (ถ้าเริ่มใหม่ให้รัน `schema.sql` ล่าสุดแทน ไม่ต้องรันไฟล์ migration)

> ใช้เฉพาะ publishable (anon) key เท่านั้น **ห้ามใช้ service_role key ในเว็บแอปนี้เด็ดขาด**

## 2) ตั้งค่าโปรเจกต์

```bash
npm install
```

คัดลอกไฟล์ `.env.example` เป็น `.env` แล้วใส่ค่าจาก Supabase Dashboard → Project Settings → API:

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable key>
```

จากนั้นรัน:

```bash
npm run dev
```

เปิดเบราว์เซอร์ที่ URL ที่แสดง (ปกติ http://localhost:5173)

**สำคัญ:** Vite อ่านไฟล์ `.env` ตอนเริ่มรันเท่านั้น ถ้าแก้ `.env` ต้องหยุดแล้วรัน `npm run dev` ใหม่

คำสั่งอื่น: `npm run build` (build สำหรับขึ้น production) และ `npm run preview` (ดูผล build)

### หมายเหตุสำหรับ Windows

ถ้า PowerShell บล็อกการรัน npm (error เรื่อง execution policy) ให้ใช้ **Command Prompt (cmd)** หรือ Git Bash แทน
หรือแก้ policy เฉพาะผู้ใช้ปัจจุบันด้วย:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## 3) ตั้ง Admin คนแรก

ผู้ใช้ที่สมัครผ่านหน้าเว็บได้บทบาท "นักเรียน" เสมอ ตั้ง Admin คนแรกด้วย SQL Editor
(รัน SQL โดยตรงไม่มี `auth.uid()` จึงแก้ role ได้ — trigger กันผู้ใช้แก้ role ตัวเองผ่านเว็บเท่านั้น):

```sql
-- สมัครผ่านหน้าเว็บก่อน 1 บัญชี แล้วรันคำสั่งนี้โดยเปลี่ยนรหัสนักศึกษา
update public.profiles set role = 'admin' where student_code = 'รหัสของคุณ';
```

เข้าสู่ระบบใหม่ (หรือรีเฟรชหน้า) จะเห็นเมนูจัดการของ Admin
จากนั้นตั้งบทบาทให้ผู้ใช้คนอื่นได้ในหน้า **ผู้ใช้** — เลือกบทบาท "ผู้จัดกิจกรรม" (organizer) ให้ผู้ที่รับผิดชอบจัดกิจกรรมของแผนก
และกำหนดระดับกิจกรรมที่ดูแลได้ในปุ่มผู้จัดกิจกรรม (เพื่อสิทธิ์ดูรายงาน)

## 4) ลำดับการใช้งานครั้งแรก

1. ตั้ง Admin ตามข้อ 3 แล้วเข้าสู่ระบบ
2. ไปที่ **หมวดและแผนก** สร้างหมวดกิจกรรม (แผนกวิชา 10 แผนกมีให้แล้วจาก schema.sql)
3. ไปที่ **จัดการกิจกรรม → สร้างกิจกรรม**: กรอกข้อมูลทั่วไป → ตั้งระดับที่เข้าร่วม (ปวช./ปวส. เลือก 1 หรือ 2,
   ทำรวม = วันเดียวกัน, ทำแยก = คนละวัน) → สร้างช่องฟอร์มในแท็บ Form Builder
4. ให้นักศึกษาสมัครเองที่หน้า `/register` แล้วลงชื่อจากหน้ากิจกรรม
5. ดูรายชื่อตัวแทนที่หน้า **รายชื่อตัวแทน** และรายงาน/ส่งออก CSV ที่หน้า **รายงาน**

## ระบบอนุมัติกิจกรรม

กิจกรรมมีสถานะ `รออนุมัติ` (pending) และ `อนุมัติแล้ว` (approved):

- **Admin สร้าง** → อนุมัติทันที นักเรียนเห็นและลงชื่อได้เลย
- **ผู้จัดกิจกรรมสร้าง** → รออนุมัติ นักเรียนยังไม่เห็นกิจกรรมนี้ (ถูกกั้นด้วย RLS ที่ฐานข้อมูล)
  ผู้จัดยังแก้ข้อมูล/ระดับ/ฟอร์มได้จนกว่าจะอนุมัติ
- **Admin กดอนุมัติ** (ปุ่มอนุมัติในหน้า จัดการกิจกรรม) → นักเรียนเห็นและลงชื่อได้ทันทีตามช่วงรับสมัครที่ตั้งไว้
  หลังอนุมัติแล้ว ผู้จัดแก้ไขกิจกรรมนี้ไม่ได้ (ล็อก) ต้องให้ Admin เท่านั้น
- การลงชื่อของนักเรียนเองไม่มีขั้นตอนอนุมัติ — เมื่อกิจกรรมอนุมัติแล้วและอยู่ในช่วงรับสมัคร ลงแล้วเป็นตัวแทนทันที
- ผู้จัดคัดลอกกิจกรรมตัวเองไปปีใหม่ได้ สำเนาใหม่จะกลับเป็นรออนุมัติ

## โครงสร้างโปรเจกต์

```
supabase/schema.sql      ฐานข้อมูลทั้งหมด รันครั้งเดียวใน SQL Editor
supabase/reset.sql       ล้างของที่ schema.sql สร้าง เพื่อรันใหม่
supabase/migration-organizer-approval.sql  อัปเดตฐานข้อมูลเดิม เพิ่มระบบผู้จัดกิจกรรม+อนุมัติ
src/api/                 ห่อการเรียก Supabase ทั้งหมด (UI ไม่เรียก supabase ตรง)
src/components/          คอมโพเนนต์กลาง (DynamicForm, layout, ui ต่างๆ)
src/context/             AuthContext (session + โปรไฟล์)
src/hooks/               React Query hooks
src/lib/                 supabase client, วันที่ พ.ศ., CSV, แปล error, สถานะรับสมัคร
src/pages/               หน้าเว็บแยกตามโมดูล (auth, events, roster, profile, admin, reports)
src/content/about.js     เนื้อหาหน้า เกี่ยวกับเรา (placeholder ให้แก้เอง)
```

## บทบาท

| บทบาท | สิทธิ์ |
|---|---|
| นักเรียน (student) | ดูปฏิทิน ลงชื่อ/แก้/ยกเลิกของตัวเอง ดูรายชื่อตัวแทน แก้โปรไฟล์ ส่งคำติชม |
| ผู้จัดกิจกรรม (organizer) | สร้างกิจกรรมเองได้ (รออนุมัติ) + แก้/ลบกิจกรรมตัวเองตอนรออนุมัติ + หน้ารายงานของกิจกรรมที่ตัวเองสร้างหรือได้รับมอบหมาย + ส่งออก CSV |
| ผู้ดูแลระบบ (admin) | ทุกอย่าง + อนุมัติกิจกรรมของผู้จัด + จัดการกิจกรรม/ฟอร์ม/หมวด/แผนก/ผู้ใช้/คำติชม |

ความปลอดภัยจริงบังคับที่ฐานข้อมูลด้วย RLS และ trigger การซ่อนเมนู/กั้นหน้าเป็นเพียง UX

## หมายเหตุการพัฒนา

- ไม่มีข้อมูลตัวอย่าง (mock/seed) ใดๆ นอกจากแผนกวิชาจริง 10 แผนกใน schema.sql
- การลงชื่อของนักเรียนไม่มีขั้นตอนอนุมัติ (ลงแล้วเป็นตัวแทนทันที) แต่กิจกรรมที่ผู้จัดกิจกรรมสร้างต้องให้ Admin อนุมัติก่อนนักเรียนจึงจะเห็น/ลงชื่อได้
- ยกเลิก/แก้คำตอบได้ก่อนปิดรับสมัครเท่านั้น (Admin ทำได้ตลอด) ข้อความ error จากฐานข้อมูลเป็นภาษาไทย
- ส่งออก CSV เป็น UTF-8 มี BOM เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน และบังคับคอลัมน์รหัสนักศึกษา/ชั้นปี/ห้อง/คำตอบฟอร์มเป็นข้อความ
  (กัน Excel แปลง `2/1` เป็นวันที่ หรือตัดเลขศูนย์นำหน้าของรหัส/เบอร์โทร)
- session จัดการโดย Supabase Auth ไม่เก็บข้อมูลสำคัญใน localStorage เอง
